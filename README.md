# SkillBridge
### A Personalized Learning Resource and Skill-Path Recommendation System

Recommendation Systems mini-project (T.Y. B.Tech, Artificial Intelligence & Data Science).
SkillBridge recommends real Coursera courses for a learner's profile, identifies the skills they are
missing for a career goal, and orders those skills into a prerequisite-respecting learning path. All three
features run on **one shared recommendation engine**.

## 1. Introduction
Online course catalogues are large and keyword search returns *matches*, not *guidance*. SkillBridge
combines several recommendation techniques taught in the course (content-based, knowledge-based,
constraint-based, collaborative, hybrid, popularity/rating baseline, association rules) behind a Streamlit
interface, and explains every ranking it produces.

## 2. Problem statement
Students struggle to find courses that match their current skills, career goal, proficiency and constraints.
Generic search does not say *what to learn next*, *which resources suit the current level*, or *which skills a
career goal needs*. SkillBridge links personalised course recommendations with a skill-gap analysis and a
structured learning path.

## 3. Objectives
1. Recommend relevant courses from a real catalogue.
2. Personalise them with a learner profile (goal, skills, level, interests, constraints).
3. Identify skill gaps relative to a career goal.
4. Recommend courses that close those gaps.
5. Order the gaps into a learning path that respects known prerequisites.
6. Explain every recommendation.
7. Compare recommendation techniques with an honest offline evaluation.

## 4. Features

the technique behind what you see.

**Coursera Courses Dataset 2021** by Khushee Kapoor, Kaggle:
https://www.kaggle.com/datasets/khusheekapoor/coursera-courses-dataset-2021 (licence listed as *Unknown* on Kaggle).

**Data flow.** `Coursera.csv → preprocessing → courses_clean.csv (+ courses_rated.csv)` →
`SkillBridgeEngine` (TF-IDF model, course–skill matrix, knowledge rules, CF model) → used by the
Recommendations, Skill-gap, Learning-path and Evaluation code.

**Caching.** The engine is built once per server with `st.cache_resource`, keyed by a fingerprint (modification
time + size) of the raw CSV, processed files, knowledge config and synthetic data; changing any of them rebuilds it.
Processed files are rebuilt automatically when older than the raw CSV. Learner profiles live only in each browser
session's `st.session_state`, so profiles of different users never share a cache entry.

**Which file each component reads.** Rating-based components (top-rated baseline, hybrid quality signal,
strict minimum-rating constraint) use only `courses_rated.csv`. Everything else uses `courses_clean.csv`.

## 8. Data preprocessing
`src/preprocessing.py` (run automatically, or with `python -m src.preprocessing`):
1. **Validate** required columns (`Course Name`, `Course URL`); missing optional columns are added as empty.
   Empty files or header-only files raise a clear error.
2. **Deduplicate**: exact duplicate rows, then duplicate URLs (98 removed).
3. **Repair text**: U+FFFD before a contraction/possessive ending (`You�ll`, `Coursera�s`) becomes an apostrophe;
   any other U+FFFD becomes a space; whitespace is normalised.
4. **Parse skills**: split on two or more spaces; the final two slugs become `domain` and `subdomain`; tags longer
   than 50 characters (description text spilled into the column in 5 malformed rows) are discarded.
5. **Ratings**: numeric values in 1–5 are kept unchanged; `"Not Calibrated"` and invalid values become missing.
   They are never imputed.
6. **Difficulty**: ordinal rank Beginner = 1, Intermediate = 2, Advanced = 3. **[Manual]** `Conversant` (undefined by
   Coursera) is ranked as 2 while its label is shown unchanged; `Not Calibrated` is unknown.
7. **IDs**: the URL slug (`coursera.org/learn/<slug>`) is the course id.

`src/rated_subset.py` then writes `courses_rated.csv`: rows of the clean catalogue whose rating parses as a
number inside the range observed in the raw file (1.0–5.0). It removed 82 rows; every retained rating was checked
to equal the raw value for the same URL (a unit test repeats this check).

## 9. Recommendation algorithms

### 9.1 Top-rated baseline (non-personalised) — `popularity.py`
Ranks rated courses by average rating (ties broken alphabetically by id; the order inside a tie means
nothing). **It is not a popularity measure**: the dataset has no number of ratings, so a weighted rating
(e.g. IMDb's `v/(v+m)·R + m/(v+m)·C`) would need a vote count `v` that does not exist. A genuine
popularity baseline (completion counts) is used only in the synthetic experiment, where counts exist.

### 9.2 Content-based filtering — `content_based.py`
Each course document = title ×2 + skill tags ×2 + description + provider, lower-cased, cleaned. TF-IDF with
English stop words, unigrams and bigrams, `min_df = 2`, `max_df = 0.5`, sub-linear term frequency.
Coursera domain/subdomain labels are **excluded** from the text because the evaluation uses them as labels.
* **Mode 1 – similar courses:** `NearestNeighbors(metric="cosine")`; the selected course is removed from its own neighbours.
* **Mode 2 – profile:** a query built from interests + desired skills + gap skills + career name, compared with every course.
* **Explanation:** the terms with the largest contribution `q_t · d_t` to the cosine similarity.

### 9.3 Knowledge-based recommendation — `knowledge_based.py`
**[Manual]** `config/skill_knowledge.json` defines 40 skills (keywords + prerequisite groups) and 11 career goals
(required skills). A course's evidence for a skill is **1.0** if a keyword appears in its skill tags or title,
**0.4** if only in its description, else 0 (regex with word boundaries). Rules, each in [0, 1]:

| Rule | Definition |
|---|---|
| Goal relevance | noisy-OR over gap skills: `1 − Π_s (1 − 0.6 · priority_s · evidence_s)`; priority 1.0 for a desired skill, 0.8 for a career requirement |
| Level fit | `1 − |difficulty_rank − proficiency_rank| / 2`; unknown difficulty → 0.5 (neutral) |
| Prerequisite readiness | share of the course's taught gap skills whose prerequisites the learner has (or the course itself teaches); the penalty is halved for Beginner courses |
| Soft preferences | difficulty, provider and minimum-rating preferences that are *not* strict |

`knowledge = (0.55·relevance + 0.20·level fit + 0.15·readiness + 0.10·preferences) / Σ weights used`, and
0 when relevance is 0. Every explanation sentence is generated from these same rules.

### 9.4 Constraint-based recommendation — `constraints.py`
| Constraint | Hard (strict) behaviour | Soft behaviour |
|---|---|---|
| Preferred difficulty | only courses at those levels (unknown difficulty excluded) | level distance lowers the score |
| Preferred providers | only those providers | +preference for them |
| Minimum rating | only genuinely rated courses ≥ threshold | rating ≥ threshold preferred; unrated neutral |
| Must-cover skills | course must directly teach ≥ 1 of them | — |
| Excluded topics | always hard | — |
| Completed courses | always excluded | — |

Hard constraints are applied **before** scoring by restricting the candidate set, so no method can return a
violating course. Each constraint's number of rejected courses is reported; when fewer than *N* courses remain,
the interface names the most restrictive constraint and offers a one-click relaxation.

### 9.5 Collaborative filtering — `collaborative_filtering.py`, `synthetic_data.py`
**Why synthetic data.** The catalogue has no users. The only related public dataset (Coursera course reviews on
Kaggle) identifies reviewers by display names such as “By Robert S”, which are not unique users, so it cannot
support honest user–item CF. **[Synthetic]** therefore `synthetic_data.py` generates 1,200 learners
(12,108 completions; mean 10.1 courses per learner) with a seeded process: each learner has a persona (career goal
and level); each course gets a random log-normal “appeal” (not derived from ratings); courses are sampled with
probability ∝ appeal × subdomain affinity × level affinity, plus 15 % uniformly random picks; picks are ordered
easier → harder. The file is stored separately in `data/sample/`, every row has `is_synthetic = True`, and the
loader refuses files without that label.

**Algorithm:** item-based k-nearest-neighbour CF on the binary learner × course matrix with shrunk cosine
similarity (§10.4). Given a learner's *completed courses* as history it scores every other course. The website does
not use it (its signal comes from simulated learners); it is evaluated in experiment C. **Cold start:** no
history → CF is unavailable and the hybrid drops it; courses no synthetic learner took score 0.
Neighbourhood size `k = 400` and shrinkage `λ = 50` were chosen by grid search on a validation split of the
synthetic **training** data. The application works fully without the synthetic file.

### 9.6 Hybrid recommendation — `hybrid.py`, `recommender.py`
Weighted combination of normalised content, knowledge, quality and (when available) collaborative scores, with
weights chosen by career-split cross-validation and an optional Maximal-Marginal-Relevance re-ranking that removes
near-duplicate courses (§11).

### 9.7 Context-aware ranking
These contextual variables change filtering or ranking: **proficiency** (level fit, path target levels),
**career goal** (gaps → relevance and content query), **existing skills** (gaps, prerequisite readiness),
**desired skills** (priority 1.0), **preferred difficulty/provider/rating** (soft or hard), **completed courses**
(exclusion, CF history). Experiment B measures the effect of proficiency (§15). Course duration is not in the
dataset, so available study time is not used.

### 9.8 Association rule mining — `association_rules.py`
Apriori (mlxtend) with courses as transactions and knowledge-base skills a course directly teaches as items;
`min_support = 0.01`, `min_confidence = 0.30`, `lift > 1`, itemsets of size ≤ 2. **[Dataset]** It finds 29 rules,
e.g. *HTML & CSS → Web Development* (confidence 0.65, lift 15.1) and *Computer Vision → Deep Learning* (0.64, 10.1).
These describe **how courses are built, not learner behaviour**; they are shown in the evaluation notebook and do
not affect rankings.

## 10. Mathematical explanations

**10.1 TF-IDF.** For term *t* in course document *d* among *N* documents:
`tf(t,d) = 1 + log(count(t,d))` (sub-linear), `idf(t) = ln((1 + N) / (1 + df(t))) + 1`,
`w(t,d) = tf(t,d) · idf(t)`, and each document vector is L2-normalised. Rare, specific terms
(“tensorflow”) get high weight; ubiquitous ones (“course”) get low weight or are removed by `max_df`.

**10.2 Cosine similarity.** `cos(a, b) = (a · b) / (‖a‖ ‖b‖)`. Because TF-IDF rows are L2-normalised, this is the
dot product. Cosine distance (used by `NearestNeighbors`) is `1 − cos`.

**10.3 Knowledge relevance (noisy-OR).** `relevance = 1 − Π_s (1 − α · p_s · e_s)` with α = 0.6, priority *p_s*,
evidence *e_s*. One strongly taught desired skill gives 0.6; two give 0.84; three 0.94 — breadth helps with
diminishing returns.

**10.4 Item-kNN collaborative filtering.** With *U_i* the learners who took course *i*:
`cos(i, j) = |U_i ∩ U_j| / √(|U_i| · |U_j|)`; shrinkage by co-occurrence count `c_ij = |U_i ∩ U_j|`:
`sim(i, j) = cos(i, j) · c_ij / (c_ij + λ)`; keep the *k* largest `sim(i, ·)` per course (the neighbourhood
N_k(i)); score `score(u, i) = Σ_{j ∈ history(u)} sim(i, j) · [j ∈ N_k(i)]`.

**10.5 Top-rated quality.** `quality = (rating − 1) / (5 − 1)` for genuinely rated courses; undefined otherwise.

## 11. Hybrid scoring formula
```
hybrid(c) = Σ_m w_m · s_m(c)  /  Σ_m w_m        summed over components m available for course c
```
| Component *m* | Score *s_m* (normalised to [0, 1]) | Weight *w_m* |
|---|---|---|
| content | TF-IDF cosine to the profile query ÷ the maximum among eligible courses | 0.1 |
| knowledge | rule score (§9.3) | 0.7 |
| quality | `(rating − 1)/4` from `courses_rated.csv` | 0.1 |
| collaborative\* | item-kNN score ÷ the maximum among eligible courses | 0.15 |

* **[Result] How the weights were chosen.** Content, knowledge and quality weights were selected by **career-split
  cross-validation** in experiment B (§14): weights are chosen on one half of the careers and scored on the other.
  The weights above are the selection on all careers; `tests/test_evaluation.py` checks that `DEFAULT_WEIGHTS`
  matches the saved selection. The earlier hand-set weights (0.35 / 0.45 / 0.20) are kept as a comparison row.
* The collaborative weight is not searched (it needs a learning history) and stays modest because its data are
  synthetic. The website calls the hybrid **without** the collaborative component (`use_collaborative=False`).
* **Diversity (MMR).** The final list is chosen greedily from the 50 best candidates:
  `next = argmax_c [λ · hybrid(c) − (1 − λ) · max_{s ∈ selected} cos(c, s)]` with λ = 0.85. This is a product
  choice: it lowers graded NDCG@10 by 0.025 and raises intra-list diversity by 0.025 (both measured, §15), and removes
  near-duplicate courses such as several “Exploratory Data Analysis” guided projects.
* A component that cannot be computed for this learner is **dropped**, never invented (no history → no CF; no
  goal/desired skills → no knowledge score). For an **unrated** course the quality weight is dropped for that course
  only; its rating is never filled in.
* Courses with no personalised evidence (content, knowledge and CF all 0) are not returned, so quality alone cannot
  promote an unrelated course.
* Scores are relative ranking scores, **not probabilities**.
* **Tried and rejected:** weighting a course's title above its noisy auto-generated skill tags lowered held-out graded
  NDCG (0.650 → 0.633), so the change was reverted.

## 12. Skill-gap analysis
`skill_gap.py`: target skills = **[Manual]** required skills of the career goal ∪ desired skills. Possessed =
target ∩ current skills; gaps = the rest (desired skills priority 1.0, career requirements 0.8). Readiness =
possessed / target. For each gap, `SkillBridgeEngine.recommend_for_skill` asks the hybrid for the best courses that
directly teach **that one skill** (the skill is the only target, so broad courses touching many gaps are not
favoured; the learner's hard filters still apply). The preferred level is the learner's *starting level* for that
skill: **Beginner** for a foundational skill they lack or one whose prerequisites they have not listed, otherwise
their overall proficiency (`learning_path.starting_rank`) — general proficiency does not transfer to a skill never
studied. Gaps are listed with ready-to-start skills first, then by prerequisite depth. **The mapping is hand-written, not learned from industry data.**

## 13. Learning-path generation
`learning_path.py` (greedy and rule-based — **not** a globally optimised curriculum):
1. Path skills = gaps + missing prerequisites of those gaps (transitively; from an *any-of* group the alternative
   already in the path is preferred).
2. **Topological order** (Kahn's algorithm) over the in-path prerequisite graph; among ready skills, lower stage
   first, then higher priority, then alphabetical.
3. **Stage** = 1 + longest in-path prerequisite chain. **Target difficulty** = the skill's starting level (see §12)
   plus one level per stage after the first, capped at Advanced.
4. For each skill `recommend_for_skill` (the same focused request as the skill-gap page) ranks courses that
   directly teach it, with that skill as the only target, earlier path skills counted as known, and the target difficulty as a soft preference. A course already in the
   path is never reused.
5. Each step records why the skill is in the path, why it is at that position, and why that course was chosen.

Prerequisites exist only where written in the config; a skill without prerequisites is treated as foundational.
If no course teaches a skill under the learner's constraints, the step is shown without a course and a note
explains why.

## 14. Evaluation methodology
`python -m src.evaluation` runs three experiments (K = 10, seed 7) and saves `reports/evaluation_results.csv`,
`reports/evaluation_pairwise.csv` and `reports/evaluation_metadata.json`. The notebook
`notebooks/evaluation_results.ipynb` presents them (tables, charts, intervals, findings), adds a **side-by-side
comparison of the recommender systems** (method overview, the same learner ranked by every system, a top-10
overlap matrix across the 99 profiles, and a scorecard), and saves the report figures to `reports/figures/`. **No user study was conducted; none of
this measures user satisfaction.**

| | A. Similar courses | B. Learner profiles | C. Interaction prediction |
|---|---|---|---|
| Data | [Dataset] | [Dataset] | **[Synthetic]** |
| Units | 400 random query courses | 99 profiles: 11 careers × 3 levels × 3 shares (0, ⅓, ⅔) of required skills known | 1,200 synthetic learners |
| Relevance label (**proxy**) | same Coursera subdomain as the query | *topic only*: course subdomain ∈ career's related subdomains ([Manual] mapping); *topic + level (graded)*: gain 2 if on-topic at the learner's level, 1 if on-topic at an adjacent level | held-out courses the learner actually took |
| Leakage control | subdomains not in TF-IDF text | labels used by no recommender; hybrid weights chosen by **career-split cross-validation** (2 folds), so every hybrid score comes from careers not used to choose its weights | per-learner split: latest 20 % = test; CF and hybrid parameters tuned on a validation split of the *training* data; asserted no train/test overlap |
| Methods | Content-based, Top-rated, Random | Hybrid (cross-validated), + diversity, Hybrid (hand-set weights), Knowledge, Content, Top-rated, Random | Hybrid (tuned / default), Item-kNN CF, Content (history), Knowledge (persona), Most-completed (synthetic popularity), Top-rated, Random, Generator oracle (upper reference) |

**Metrics** (for a ranked list *L* of length *k* and relevant set *R*):
* Precision@k = |L ∩ R| / k; Recall@k = |L ∩ R| / |R|; HitRate@k = 1 if |L ∩ R| > 0.
* NDCG@k = DCG / IDCG with `DCG = Σ_{i=1..k} rel_i / log2(i + 1)` and IDCG the DCG of `min(|R|, k)` hits first.
  The graded variant uses gains 0/1/2 instead of 0/1 and the ideal ordering of all gains.
* MRR@k = 1 / rank of the first relevant item (0 if none).
* Catalogue coverage = |∪ L| / |catalogue|.
* Intra-list diversity = mean pairwise `1 − cos` between TF-IDF vectors in a list.
* Gap coverage@10 = share of the learner's gap skills directly taught by ≥ 1 recommended course.
* Level fit@10 = share of recommendations whose difficulty equals the learner's proficiency.
* Beginner-vs-Advanced overlap = Jaccard of the top 10 for the same goal/skills at the two extreme levels.
* Units with no relevant items are skipped for recall/NDCG (counts saved in `n_evaluated`).
* **Significance:** paired bootstrap (1,000 resamples) of per-unit NDCG@10 differences, 95 % percentile interval;
  no multiple-comparison correction.

**Caveats.** The relevance labels in A and B are proxies; B's labels and the knowledge-based / content-based
queries are both driven by the career goal, so B partly measures *agreement with the manual career model*. The
graded label was introduced because the topic-only label cannot see whether a course suits the learner's level;
both labels are reported.
MAE/RMSE are not reported because no rating prediction is performed.

**Findings (honest reading).**
* **A:** TF-IDF similar-course retrieval agrees with Coursera's editorial subdomains far more than chance
  (NDCG 0.56 vs 0.04).
* **B:** choosing the hybrid's weights by career-split cross-validation raised held-out graded NDCG from 0.550
  (hand-set weights) to 0.650 and level fit from 59 % to 85 %; the cross-validated hybrid is significantly better than
  content-based (+0.246) and knowledge-based (+0.088) on the graded topic-and-level label. On the *topic-only* label
  content-based remains best (0.778 vs 0.701): it finds on-topic courses but ignores the learner's level (level fit
  33 %, identical lists for Beginner and Advanced learners). The website's diversification costs 0.025 graded NDCG
  for measurably more varied lists.
* **C (synthetic):** the task is very noisy — even the generator's own weights reach only NDCG 0.071. Simple
  completion-count popularity is the strongest method; item-kNN CF is significantly *below* it, and the tuned hybrid
  is statistically indistinguishable from both CF and popularity. CF does beat content-based history and covers far
  more of the catalogue than popularity. These numbers only describe recovery of the generator's patterns.

## 16. Limitations
* **Data:** a 2021 snapshot; no rating counts, enrolments, durations, prices or prerequisites. Skill tags are
  auto-generated and noisy (e.g. *“euler's totient function”* tags 144 courses; some C++ courses carry a *python*
  tag), and some difficulty labels look wrong (*Learn to Program: The Fundamentals* is labelled Advanced).
* **Manual knowledge:** 40 skills and 11 careers written by hand; keyword matching misses synonyms and can match
  incidental mentions. Prerequisites are a simplification.
* **Collaborative filtering** is trained only on synthetic data; it cannot reflect real co-enrolment.
* **Evaluation** uses proxy labels and synthetic data; there is no user study, so no claim about satisfaction or
  learning outcomes is made. Default hybrid weights were set by judgement, not tuned on real data.
* **Learning path** is greedy; it does not optimise total time, cost or redundancy, and stage-based target
  difficulty can jump to Advanced quickly for deep prerequisite chains.
* Profiles live in the browser session only (no login or persistence).

## 17. Future improvements
**[Future]** Real interaction data (e.g. institution course histories) for genuine CF and evaluation; a small user
study; learning skill requirements from job postings; embeddings (e.g. sentence-transformers) to complement TF-IDF;
course duration and cost constraints; optimising paths for total time; persisting profiles; feedback buttons that
update the profile.

## 18. Installation
Requires Python 3.11+ (developed and tested on Python 3.13.7, macOS).
```bash
cd SkillBridge
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**Cloning onto another machine.** `.venv/` and `data/raw/Coursera.csv` are not committed (see `.gitignore`), so
after `git clone` create the virtual environment as above and put the CSV in `data/raw/` (next step). The processed
files, synthetic data and evaluation reports are committed and are rebuilt automatically when the raw CSV is newer.
If the repository is private, you may instead commit the CSV by deleting the `data/raw/*.csv` line from `.gitignore`
(the Kaggle page lists the licence as *Unknown*, so avoid publishing it in a public repository).

## 19. Dataset placement

## 22. Demonstrating the project
Suggested 10-minute sequence (it follows the website's own steps 1 → 4):
1. **Home** — what the app does and the dataset statistics (computed live); point out the four-step journey.
2. **1 · Profile** — pick the *Beginner → Data Scientist* example; open *Filters* (tagged constraint-based) to show
   preferences vs. *Only these* hard filters. Click **Next: your skill gaps**.
3. **2 · Skill gaps** (knowledge-based) — readiness, have vs. to-learn, and the best courses for each gap.
   Click **Next: courses for you**.
4. **3 · Courses for you** — the featured top pick and the cards (match bar: hover for the score). Switch between
   *Best match* (hybrid), *Fill my skill gaps* (knowledge-based) and *Match my interests* (content-based): the
   technique tag and the list change together.
5. Back in Profile, set level to **Advanced**, clear the difficulty filter and save: the courses move from Beginner to
   mostly Advanced (context-aware ranking).
6. In *Filters* set **Difficulty = Beginner (Only these)** and **Must teach = MLOps & Model Deployment**: a
   constraint-based tag appears, the page says only a few courses match, and offers to loosen the most restrictive
   filter.
7. **Similar courses** tab (content-based nearest neighbours) — pick *Python Data Structures*; the course itself is
   never returned.
8. **4 · Learning path** (prerequisite graph + hybrid) — stages, "builds on" links, CSV export.
9. **Evaluation (notebook)** — open `notebooks/evaluation_results.ipynb` and walk through A, B and C, emphasising the
   cross-validated hybrid, the synthetic-data warning, the oracle row and the bootstrap intervals; section 6 compares
   the systems side by side (same learner, overlap matrix, scorecard).

Files worth opening during questions: `src/recommender.py` (engine), `src/knowledge_based.py` (rules),
`src/hybrid.py` (formula), `src/learning_path.py` (topological ordering), `src/evaluation.py` (metrics),
`config/skill_knowledge.json` (manual knowledge).
